# Database Design

## Stack

- **Database**: PostgreSQL 15+
- **ORM**: SQLAlchemy 2.x with type hints
- **Migrations**: Alembic
- **Driver**: `psycopg` (async-ready, modern PostgreSQL driver)
- **Connection URL**: `postgresql+psycopg://[user]:[password]@[host]:[port]/[database]`

## Environment

- `DATABASE_URL` is loaded from environment variables via `backend/app/core/config.py`
- Example value in `backend/.env.example` is placeholder-only
- No credentials are hardcoded in application code
- Connection pool uses `pool_pre_ping=True` for health checks

## Architecture

### Base Model Pattern

All models inherit from `Base` class and optionally use `TimestampMixin` for audit trails:

```python
class MyModel(Base, TimestampMixin):
    __tablename__ = "my_table"
    # ... columns ...
```

**TimestampMixin** automatically adds:
- `created_at: DateTime(timezone=True)` - server default: `now()`
- `updated_at: DateTime(timezone=True)` - server default: `now()`, updated on changes

### Data Integrity

All tables use:
- **UUID primary keys** for globally unique identifiers
- **Check constraints** for business rule validation
- **Foreign key constraints** with `RESTRICT` delete behavior to prevent orphaning
- **Unique constraints** on business identifiers (slug, email)
- **Index strategy** tailored to query patterns

## Schema (Production-Hardened)

### tools

**Purpose**: Available AI tools on the platform

| Column | Type | Constraints | Index | Notes |
|--------|------|-------------|-------|-------|
| `id` | UUID | PRIMARY KEY, default: uuid4() | - | Unique identifier |
| `slug` | String(120) | UNIQUE, NOT NULL, check: len > 0 | YES | URL-friendly (e.g., `translator`) |
| `name` | String(200) | NOT NULL, check: len > 0 | - | Display name (e.g., `Translator`) |
| `description` | Text | nullable | - | Detailed functionality description |
| `category` | String(120) | nullable | - | Tool category (language, form, legal, etc.) |
| `is_active` | Boolean | default: true | - | Feature flag for availability |
| `created_at` | DateTime(tz) | NOT NULL, default: now() | - | Audit trail |
| `updated_at` | DateTime(tz) | NOT NULL, default: now(), onupdate | - | Audit trail |

**Relationships**: 
- `1:N` with `ToolUsage` (cascade: all, delete-orphan - usage records are tied to tool lifecycle)

**Queries optimized for**:
- List active tools: `WHERE is_active = true ORDER BY created_at`
- Get tool by slug: Direct UNIQUE index lookup

### tool_usage

**Purpose**: Track individual tool execution events for analytics and usage-based features

| Column | Type | Constraints | Index | Notes |
|--------|------|-------------|-------|-------|
| `id` | UUID | PRIMARY KEY, default: uuid4() | - | Unique event identifier |
| `tool_id` | UUID | FK → tools.id (RESTRICT), NOT NULL | YES (single) | Prevents tool deletion if usage exists |
| `session_id` | String(255) | NOT NULL | YES (single + composite) | Anonymous user session tracker |
| `ip_hash` | String(255) | nullable | - | Hashed IP for abuse detection (privacy-preserving) |
| `language` | String(50) | nullable | - | Language code (en, ne, etc.) |
| `input_tokens` | Integer | default: 0, check: >= 0 | - | Tokens sent to AI provider |
| `output_tokens` | Integer | default: 0, check: >= 0 | - | Tokens generated by AI provider |
| `status` | String(50) | NOT NULL, check: len > 0 | - | Result (success, error, rate_limited, etc.) |
| `created_at` | DateTime(tz) | NOT NULL, default: now() | YES (composite) | Event timestamp |
| `updated_at` | DateTime(tz) | NOT NULL, default: now(), onupdate | - | Audit trail |

**Indexes**:
- `ix_tool_usage_tool_id` - Single column (FK lookup)
- `ix_tool_usage_session_id` - Single column (abuse detection, daily limits)
- `ix_tool_usage_session_created` - Composite (session + time filtering)
- `ix_tool_usage_tool_created` - Composite (aggregation queries)
- `ix_tool_usage_session_status` - Composite (abuse patterns, status counts)

**Relationships**:
- `N:1` with `Tool` (many usages per tool)

**Queries optimized for**:
- Count daily usage per session: `WHERE session_id = ? AND DATE(created_at) = TODAY`
- Count usage by tool: `GROUP BY tool_id, COUNT(*)`
- Distinct users: `COUNT(DISTINCT session_id)`
- Latest usage records: `ORDER BY created_at DESC LIMIT 10`

| `target_group` | String(255) | nullable | - | Intended beneficiary group |

**Queries optimized for**:

## Migrations

### Migration Strategy

- **Tool**: Alembic with version control
- **Location**: `backend/alembic/versions/`
- **Naming**: `YYYYMMDD_NNNN_<description>.py`
- **Tracking**: `alembic_version` table stores current schema version

### Migration Timeline

| Revision | Date | Description | Status |
|----------|------|-------------|--------|
| `20260508_0001` | 2026-05-08 | Initial schema with 5 tables | Applied |
| `20260612_0002` | 2026-06-12 | Production hardening: indexes, constraints, relationships | Pending |

### Migration Practices

- **Upgrade path** only: Focus on forward migrations
- **Downgrade support**: Provided for development rollback
- **Idempotent operations**: Safe to rerun without duplicates
- **No data loss**: Migrations preserve existing data during schema evolution

### Running Migrations

```bash
cd backend

# Show current schema version
alembic current

# Show pending migrations
alembic history

# Apply migrations
alembic upgrade head

# Rollback one migration
alembic downgrade -1
```

## Performance Considerations

### Index Strategy

**Indexes are created for**:
1. **Foreign keys** - Join performance
2. **Unique constraints** - Uniqueness enforcement and equality lookups
3. **Filtering columns** - WHERE clauses (session_id, status, email, created_at)
4. **Composite patterns** - Common multi-column filters (session_id + created_at)
5. **Aggregation columns** - GROUP BY and COUNT DISTINCT queries

**Index sizing**:
- `ix_tool_usage_session_id`: High cardinality (millions of sessions)
- `ix_tool_usage_created`: High cardinality (time-series data)
- `ix_sponsor_lead_email`: Medium cardinality (thousands of leads)
- `ix_sponsor_lead_status`: Low cardinality (few status values)

### Query Patterns

**Heavy queries** (optimized):
- `distinct_users_helped_count()` - `COUNT(DISTINCT session_id)` on `tool_usage`
  - **Optimization**: `session_id` is indexed
- `usage_count_by_tool()` - `GROUP BY tool_id, COUNT(*)` on `tool_usage`
  - **Optimization**: `ix_tool_usage_tool_created` enables efficient grouping
- `latest_tool_usage()` - JOIN with `ORDER BY created_at DESC LIMIT 10`
  - **Optimization**: Composite index `(tool_id, created_at)` supports both join and sort
- `count_daily_by_session()` - `WHERE session_id = ? AND DATE(created_at) = TODAY`
  - **Optimization**: `ix_tool_usage_session_created` supports both filters

### Data Volume Estimates (MVP)

Assuming 100 active sessions and 10,000 tool invocations per day:

- `tool_usage`: ~300K rows/month
- `sponsor_leads`: ~50 rows/month
- `admin_users`: <10 rows
- `tools`: 5 rows
- `sponsor_packages`: 3-5 rows

**Total DB size**: <100 MB (well within Supabase free tier of 500 MB)

### Scalability Notes

- **Row limits**: No tables approach limits (<1M rows)
- **Connection pooling**: `pool_pre_ping=True` ensures healthy connections
- **Migration strategy**: Zero-downtime add-only, backward-compatible changes
- **Future caching**: Application-level caching (Redis) recommended at >1M rows/month

## Development Workflow

### Creating a New Model

1. Define model in `backend/app/models/<model_name>.py`
2. Inherit from `Base` and optionally `TimestampMixin`
3. Use `mapped_column()` with type hints for all columns
4. Add indexes and constraints via `__table_args__`
5. Export in `backend/app/models/__init__.py`

### Creating a New Migration

```bash
cd backend
alembic revision --autogenerate -m "brief description"
alembic upgrade head
```
